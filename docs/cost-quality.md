# 成本–质量–延迟：同集合决策记录

> 2026-10-19 · 数据源：`eval_results/registry.jsonl` + `eval_results/analysis/p5_baseline_report.md`
> 目的：把“哪个模块值得留”翻译成可复核的成本 / 延迟 / 质量 trade-off。
> **只比较同集合、同一晚的 dev 60 运行**（2026-10-13 20:37–21:04，DeepSeek 同一计价时段）；holdout 不参与成本对比。

## 1. 同集合对照

| 运行 | 变更 | n | 答案正确性 | 误拒率 | 成本/题 | 总成本 | p50 | p95 |
|---|---|---:|---:|---:|---:|---:|---:|---:|
| `20261013-003` R1 | 基线（HyDE on + 重排） | 60 | 0.692 | 23.1% | ¥0.0201 | ¥1.2074 | 9.56s | 14.36s |
| `20261013-005` A2 | HyDE off（最终配置） | 60 | 0.725 | 23.1% | ¥0.0112 | ¥0.6739 | 5.24s | 10.61s |
| `20261013-004` A1 | 移除重排 | 60 | 0.569 | 36.5% | ¥0.0032 | ¥0.1935 | 7.53s | 13.09s |

> R1 的答案正确性取 `p5_baseline_report.md` §1（registry 未存 judge 指标）；成本 / 延迟取 registry 原值。
> R1 的 judge 覆盖率在 registry 中为 0.9878（rejudge 回填前）；P5 报告回填后为 164/164。两者口径不同，别混用。

## 2. 两个决策

### 决策一：HyDE 关闭（采纳）

| 维度 | R1 → A2 | 读法 |
|---|---|---|
| 答案正确性 | 0.692 → 0.725（+3.3pp，p=0.724） | 不显著；质量不劣 |
| 误拒率 | 23.1% → 23.1% | 不变 |
| 成本/题 | ¥0.0201 → ¥0.0112（−44.2%） | 每千次省 ¥8.89 |
| p50 延迟 | 9.56s → 5.24s（−45.1%） | 每千次少等 4.3 秒 |
| p95 延迟 | 14.36s → 10.61s（−26.1%） | 长尾也改善 |

**结论**：质量没有可检出损失，成本 −44%、p50 −45%。HyDE 默认关闭（DR-003）。
**业务读法**：按 100 万次/月算，API 成本约省 ¥8,900/月；对客服场景，p50 从 9.6s 降到 5.2s 的体验收益可能大于省下的钱。

### 决策二：重排不能为了省钱删掉（驳回 A1）

| 维度 | R1 → A1（移除重排） | 读法 |
|---|---|---|
| 成本/题 | ¥0.0201 → ¥0.0032（−84.0%） | 每千次省 ¥16.90 |
| 误拒率 | 23.1% → 36.5%（+13.5pp，p=0.023） | 唯一显著的质量损失 |
| 答案正确性 | 0.692 → 0.569（−12.3pp） | 明显下降 |
| p50 延迟 | 9.56s → 7.53s（−21.2%） | 比 A2 还慢 |

**结论**：重排是唯一显著的边际贡献（误拒 p=0.023）；省下的 ¥16.90/千次，换来的是每千次多约 135 次误拒。

## 3. 单位经济：误拒转人工的敏感性

假设：每 1000 次查询，移除重排多 134.6 次误拒；只有其中一部分会转人工。下表给出不同“误拒→转人工”比例下的收益/成本：

| 误拒转人工比例 | 避免的转人工/千次 | 每次 ¥8 时避免损失 | 重排成本/千次 | 净收益 |
|---:|---:|---:|---:|---:|
| 10% | 13.5 | ¥108 | ¥16.9 | +¥91 |
| 50% | 67.3 | ¥538 | ¥16.9 | +¥521 |
| 100% | 134.6 | ¥1,077 | ¥16.9 | +¥1,060 |

**盈亏平衡**：在“100% 误拒都转人工”的假设下，单次转人工成本只要高于 **¥0.13**，重排的 API 成本就被覆盖；即使只有 10% 转人工，盈亏平衡点也只有 **¥1.26/次**。  
**边界**：¥8/次是外部假设，不是本项目实测；实际转人工成本、转人工率需用业务数据替换。重排成本只算 API，不含工程/运维。

## 4. Holdout 验收记录（不参与成本对比）

| 运行 | n | 答案正确性 | 误拒率 | Recall@5 | 成本/题 | p50 | p95 |
|---|---:|---:|---:|---:|---:|---:|---:|
| `20261014-004` acceptance | 20 | 0.667 | 16.7% | 0.800 | ¥0.0140 | 4.89s | 9.21s |

**读法**：holdout 是不同题目、不同日期的独立验收，只报总指标。**不要**把 16.7% 与 dev 的 23.1% 直接比较，也不要用它推导“误拒下降”的业务收益。它与 dev 同配置对照的置信区间交叠，结论是“无过拟合信号”，不是“质量提升”。

## 5. 不要这样读

1. **不要跨集合**：dev 23.1% → holdout 16.7% 不是同一个集合，不能当因果提升。
2. **不要跨计价时段**：R1/A1/A2 都在 2026-10-13 20:37–21:04 跑，才可直接比成本；其他 run 可能落在高峰价。
3. **不要把 API 成本当总成本**：不含工程、基础设施、人工复核、重试；这些在真实业务里往往更大。
4. **不要把“省 44%”说成绝对值**：绝对差是 ¥0.0089/次；是否值得取决于查询量。
5. **不要把重排的收益说成“准确率提升”**：唯一显著项是误拒率（p=0.023）；答案正确性的 −12.3pp 不显著，别过度解读。

## 6. 面试一句话

> “我不只看准确率：同一批 60 题上，HyDE 关掉质量不变、成本降 44%、p50 快 45%；把重排删掉能省 84% 成本，但误拒率从 23.1% 涨到 36.5%（p=0.023），所以重排留着。按每千次 ¥16.9 的重排成本和每次转人工 ¥8 的假设，只要 10% 的误拒会转人工，这笔钱就是划算的。”
